# Parrot LMS

A production-grade Learning Management System. Next.js (App Router) delivers the course platform — browsing, lessons, progress tracking, analytics, admin course/content management — while **WordPress + WooCommerce owns user identity, passwords, checkout, payments, and course-purchase access**. MongoDB (via Prisma) stores everything the learning experience itself needs: course content, structure, progress, quizzes, notifications, and a fast cache of who's purchased what.

```
WordPress (identity, passwords, checkout, orders)
        │  REST API (server-to-server, API-key authenticated)
        │  + signed webhooks on purchase/refund
        ▼
Next.js (course platform, learning experience, admin CMS)
        │
        ▼
MongoDB (course content, progress, analytics, purchase-access cache)
```

See [`wordpress-plugin/course-platform-bridge/readme.txt`](./wordpress-plugin/course-platform-bridge/readme.txt) for the WordPress-side integration details.

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript (strict) · Tailwind CSS v4 · shadcn/ui (Base UI) · Prisma 6 on MongoDB · Auth.js v5 · Zod · Zustand · Recharts · Tiptap · Vitest · Playwright.

**Note on Prisma:** pinned to 6.19.3, not 7.x — Prisma 7 dropped MongoDB support ("coming soon" per their own docs as of this writing). Don't upgrade the `prisma`/`@prisma/client` packages without checking that's changed.

## Architecture

A modular monolith. Business logic lives under `src/features/<domain>/{schemas,services,repositories,types,actions}`; UI lives under `src/app` (routes) and `src/components` (presentational only — no business logic in components). See `AGENTS.md` (auto-generated by Next.js) for framework-level notes, and the domain folders themselves for the real map: `auth`, `users`, `courses`, `modules`, `lessons`, `enrollments`, `progress`, `analytics`, `access` (WooCommerce purchase-access cache), `quizzes`, `media`, `notifications`, `search`.

Authorization is always enforced server-side (`src/lib/permissions`, each service's own checks) — never trust a client-supplied role, ownership, or "has access" claim.

## Local setup

### 1. MongoDB

Needs to run as a **replica set** (even single-node) — Prisma uses multi-document transactions for progress recalculation, which plain standalone MongoDB doesn't support.

- **Docker** (see `docker-compose.yml`): `docker compose up -d`
- **No Docker**: download a portable MongoDB build (e.g. from mongodb.com) and run:
  ```bash
  mongod --replSet rs0 --port 27017 --dbpath <some-dir> --bind_ip 127.0.0.1 &
  mongosh --eval "rs.initiate({_id:'rs0',members:[{_id:0,host:'127.0.0.1:27017'}]})" mongodb://127.0.0.1:27017
  ```
- **MongoDB Atlas** free tier: already a replica set, no extra config.

### 2. WordPress + WooCommerce (identity & purchases)

The app **will not start** without a reachable WordPress site running the `course-platform-bridge` plugin — every login goes through it.

```bash
bash scripts/setup-local-wordpress.sh
```

This downloads a portable PHP build, WordPress, WooCommerce, and the official SQLite integration plugin (so no MySQL/Docker/admin rights are needed), assembles a site under `.wordpress-dev/`, installs this repo's `course-platform-bridge` plugin, and creates demo users + WooCommerce products + a couple of completed orders matching `prisma/seed.ts`. It also appends the matching `WORDPRESS_*` values to `.env` automatically. Safe to re-run (idempotent).

Start it (the script prints the exact command; default port 8090):

```bash
"./.wordpress-dev/php/php.exe" -S 127.0.0.1:8090 -t "./.wordpress-dev/site" "./.wordpress-dev/site/router.php"
```

Already have a real WordPress + WooCommerce site instead? Skip the script: install the `course-platform-bridge` plugin there (copy `wordpress-plugin/course-platform-bridge/` into `wp-content/plugins/`, activate it), define the three `COURSE_PLATFORM_BRIDGE_*` constants in its `wp-config.php`, create WooCommerce products with a `_course_id` meta field matching your course slugs, and point `.env`'s `WORDPRESS_URL` at it.

### 3. Environment

```bash
cp .env.example .env
# fill in DATABASE_URL, AUTH_SECRET (npx auth secret), and the WORDPRESS_* values
# (setup-local-wordpress.sh fills the WORDPRESS_* ones in for you)
```

### 4. Install, generate, seed, run

```bash
npm install
npm run db:push      # sync the Prisma schema to MongoDB
npm run db:seed      # demo courses/lessons/quizzes -- matches the WordPress demo data above
npm run dev
```

Open http://localhost:3000.

## Testing the purchase flow end-to-end

1. Register a new account in the app, or log in as one of the demo students.
2. Visit a course you (or they) haven't purchased — you'll see "Buy this course" instead of "Continue learning".
3. That link opens WooCommerce checkout on the WordPress site. Complete the order (or, for scripted testing, use WP-CLI: `wp wc shop_order create --customer_id=<id> --status=pending --line_items='[{"product_id":<id>,"quantity":1}]' --user=1`, then `wp wc shop_order update <order-id> --status=completed --user=1`).
4. The plugin's webhook fires to `/api/webhooks/woocommerce`; the course unlocks immediately, no re-login needed.
5. Refunding/cancelling the order revokes access the same way.
